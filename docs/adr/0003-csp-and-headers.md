# 0003. CSP, headers and trailing slashes on Cloudflare (Workers static assets)

- Status: Proposed
- Date: 2026-10-22
- Deciders: Jannis Hell (pending)
- Spike: S0b, Gatsby to Astro migration ([#987](https://github.com/Primajin/eyesbound/issues/987))
- Related: [0001](0001-prismic-data-layer.md) (same-origin images, trailing-slash parity), [0002](0002-test-strategy-and-offline.md) (csp-utils.js fate, service worker)

## Context

Today's CSP is a `<meta http-equiv>` tag generated by `gatsby-plugin-csp`. `csp-utils.js` appends the SHA-256 of every inline script to its `script-src`. `gatsby-plugin-netlify` adds HSTS. The policy contains `'unsafe-inline'` and `'unsafe-eval'` for the whole site, plus origins that are no longer needed (Prismic previews, `app.netlify.com`, Gatsby dev hosts, `ws:`, `localhost:*`).

On Cloudflare, headers come from a static `_headers` file. There is no per-request code, so there are no nonces. Only hashes, `'self'` and host sources are possible. Only two routes load Google Maps: `/worldmap/` and `/picture/<uid>/` (the map island, `src/components/molecules/map.jsx`, which uses `LoadScript` from `@react-google-maps/api` with the light and dark vector `mapId`s from `src/constants/map.js`).

### Hosting target correction

The spike found that, with the current Wrangler (4.151.3), `wrangler pages project create` and `wrangler pages deploy` do **not** create a classic Pages project. They print "Delegating to the latest version of Cloudflare Pages, now part of Cloudflare Workers" and create a Worker with static assets. Classic Pages is reachable only with `--force`, which was not used. This ADR therefore targets **Cloudflare Workers with static assets** (an assets-only Worker, no `main` script). Wherever the issue and the agent docs say "Cloudflare Pages", read this. The file formats are the same (`_headers`, `_redirects`), but see "Behaviour observed" below.

## Spike method

- Test Worker `eyesbound-csp-spike` on `*.workers.dev`, free plan, static assets only. The deployment was assets-only (no Worker code), so it makes no Worker invocations. Four versions were deployed (two came from the `pages` commands delegating, two from `wrangler deploy`).
- Headless Chromium (Playwright) against the deployed URL, recording `securitypolicyviolation` events and console errors.
- Test page: minimal HTML that injects the Maps JS API script the way `LoadScript` does, then creates a vector map (`mapId`), a `Marker` and an `InfoWindow`. It used the Maps key that is already shipped publicly in the live bundle. The key is not recorded anywhere in this repo.

### What the Maps tests show, and what they cannot show

The shipped key is referrer-restricted: every variant ended with `RefererNotAllowedMapError`. The map never rendered, and I did not spoof a referrer. Results are therefore valid for loading the API but not for the render phase, which is where `'unsafe-eval'`, workers and WebGL would matter.

| Variant | `script-src` | CSP violations | `initMap` ran | Map rendered |
|---|---|---|---|---|
| a | `'self'` + inline hash + `maps.googleapis.com` + `'unsafe-eval'` | 0 | yes | no (key referrer) |
| b | `'self'` + inline hash + `'strict-dynamic'` | 0 | yes | no (key referrer) |
| c | `'self'` + inline hash + `maps.googleapis.com` (no eval) | 0 | yes | no (key referrer) |
| d | as c + `'wasm-unsafe-eval'` | 0 | yes | no (key referrer) |
| e | `'self'` + hash + `'strict-dynamic'` + `'unsafe-eval'` | 0 | yes | no (key referrer) |
| control | hash deliberately wrong | inline script blocked and reported | no | n/a |

The control proves that enforcement and violation capture work. The shared `img-src`, `connect-src`, `worker-src`, `font-src` and `style-src` were used in all variants (see MAP policy below) and produced no violations during load.

**Conclusion on `'unsafe-eval'` vs `'strict-dynamic'`.**

1. `'strict-dynamic'` with a static hash does load the Maps loader and its follow-on scripts when the loader is an inline script allowed by hash (variants b, e). Under `'strict-dynamic'` browsers ignore `'self'` and host sources. Every other script, including Astro's own external island modules (`<script type="module" src>`), would also need a hash plus `integrity`, or a nonce. This follows from the CSP3 spec and was not tested. A static `_headers` file cannot supply this, so `'strict-dynamic'` is **not recommended** for routes that hydrate Astro islands. Google's own strict example relies on nonces.
2. Google's documentation ([CSP guide](https://developers.google.com/maps/documentation/javascript/content-security-policy)) lists `'unsafe-eval'` in both its strict and its allowlist sample. Whether the current API still needs it at render time is **unverified** (see Follow-up). The proposal keeps it, but only on the two map routes. That is already a large improvement over today, where it is enabled site-wide.

## Decision

### 1. Per-route layout

| Route | Policy |
|---|---|
| everything (`/*`) | STRICT |
| `/worldmap/*` | MAP (replaces STRICT) |
| `/picture/:uid/` | MAP (replaces STRICT) |
| `/picture/` (listing, no map) | STRICT |
| `/_astro/*` | cache headers only, no CSP (static JS/CSS/images, not documents) |

Verified behaviour of `_headers` on Workers static assets (see "Behaviour observed"):

- Matching rules **accumulate**. A second `Content-Security-Policy` on an overlapping rule is sent as a **second header line**. Browsers enforce both, so the effective policy is the intersection and the looser map policy has no effect. Map rules must therefore start with `! Content-Security-Policy` (detach), then set their own. Verified.
- `/picture/*` also matches `/picture/` (the listing). A later, more specific rule with detach and re-add did **not** win in the test. The placeholder form `/picture/:uid/` matches only the detail pages (it does not match `/picture/`), so the listing keeps STRICT. Verified.

### 2. STRICT policy (all non-map routes)

```
default-src 'none'; script-src 'self' __INLINE_SCRIPT_HASHES__; style-src 'self'; img-src 'self' data:; font-src 'self'; connect-src 'self'; manifest-src 'self'; worker-src 'self'; base-uri 'self'; form-action 'self'; frame-ancestors 'none'; object-src 'none'
```

Assumptions that must be enforced by build settings and the Playwright smoke suite (ADR 0002), because they are not yet testable:

- Images are same-origin (ADR 0001), so `img-src 'self' data:`.
- No Emotion at runtime. Set Astro `build.inlineStylesheets: 'never'` and `vite.build.assetsInlineLimit: 0`, so there is no inline `<style>` and no inline module script. If `style=""` attributes remain, add `style-src-attr 'unsafe-inline'` rather than `'unsafe-inline'` in `style-src`.
- The only inline script expected is the pre-paint theme script (ADR 0002). It is covered by a hash.
- Fonts are self-hosted (`@fontsource/montserrat`), so no `fonts.googleapis.com` or `fonts.gstatic.com` in STRICT.
- Prismic preview origins, Netlify, Gatsby dev hosts, `ws:` and `localhost:*` are all dropped.

### 3. MAP policy (`/worldmap/*` and `/picture/:uid/`)

```
default-src 'none'; script-src 'self' https://maps.googleapis.com https://*.gstatic.com https://*.ggpht.com https://*.google.com https://*.googleusercontent.com 'unsafe-eval' blob: __INLINE_SCRIPT_HASHES__; style-src 'self' 'unsafe-inline' https://fonts.googleapis.com; img-src 'self' data: blob: https://maps.gstatic.com https://*.googleapis.com https://*.gstatic.com https://*.ggpht.com https://*.google.com https://*.googleusercontent.com; font-src 'self' https://fonts.gstatic.com; connect-src 'self' https://*.googleapis.com https://*.gstatic.com https://*.google.com data: blob:; worker-src 'self' blob:; manifest-src 'self'; base-uri 'self'; form-action 'self'; frame-ancestors 'none'; object-src 'none'
```

Notes:

- The origin set is Google's documented allowlist. The old config had `*.googleapis.com`, `www.gstatic.com`, `maps.gstatic.com` and `*.ggpht`, which the proposal widens only slightly (`gstatic`, `google.com`, `googleusercontent.com`). Each extra host should be dropped again if the report-only run (Follow-up) shows it is unused. `blob:` in `script-src` and the `google.com` hosts are likewise unverified.
- `style-src 'unsafe-inline'` is required on map routes. The Maps API injects `<style>` elements, and without a nonce there is no alternative.
- `frame-src` is not set, so it falls back to `default-src 'none'`. `streetViewControl` is false and the InfoWindow is not an iframe. The old Prismic and Netlify frame origins are dropped.
- Load Maps from the island's bundled JS (as `LoadScript` does today), not from an inline script. That keeps the map routes free of an inline-script hash and of `'unsafe-inline'` in `script-src`.

### 4. `csp-utils.js` and hashing

The role shrinks but does not fully disappear.

- Goal: no inline scripts, so no hashes. The pre-paint theme script is the exception. It may be externalised as a small blocking `<script src>` (small cost) or kept inline with a hash.
- If any inline script remains, replace the meta-tag rewriting in `csp-utils.js` with a post-build Astro integration. It collects the SHA-256 of every inline script in `dist/**/*.html` and substitutes `__INLINE_SCRIPT_HASHES__` in `dist/_headers`. The logic in `findHtmlFiles` and the hash computation can be reused. Keep the unit tests (ADR 0002 marks them "KEEP (conditional)": condition is met only in this case).
- Add a CI check that fails if an inline script has no hash: the Playwright smoke test already asserts no console CSP violations.
- Limits that matter for this approach: `_headers` allows 100 rules and 2,000 characters per line, free plan included. The hash list on `/*` must stay well below that. Duplicated inline scripts share a hash, so the list is short.
- Delete `gatsby-plugin-csp` configuration with Gatsby. A meta CSP cannot carry `frame-ancestors`, so the header is better in any case.

### 5. Other headers (all routes)

```
Strict-Transport-Security: max-age=31536000; includeSubDomains
X-Content-Type-Options: nosniff
Referrer-Policy: strict-origin-when-cross-origin
Permissions-Policy: camera=(), microphone=(), geolocation=(), payment=(), usb=(), interest-cohort=()
```

- **HSTS.** Observed on the live site: `max-age=31536000` only. `gatsby-config.js` asks for `includeSubDomains; preload`, but the live response does not show that. Start with `max-age=31536000; includeSubDomains`. Adding `preload` is effectively irreversible, so it needs an explicit human decision. The header is only meaningful on the custom domain, not on `workers.dev`.
- **Cache.**
  - HTML: default `public, max-age=0, must-revalidate` (observed on Workers: this default plus an ETag). Leave it.
  - `/_astro/*`: `public, max-age=31536000, immutable` (verified, no CSP header on these).
  - `/sw.js`: `Cache-Control: no-cache` (verified). The live Gatsby `/sw.js` is served `public,max-age=0,must-revalidate`, so this is equivalent or stricter.
- **Service worker kill-switch.** Returning visitors have the Gatsby Workbox worker (`gatsby-plugin-offline`) registered, and it serves precached HTML. Whatever ADR 0002 decides about offline support, `/sw.js` must exist at cutover: either a new worker or a small self-unregistering one. Without it, old pages and stale precaches can persist on returning devices.
- `X-Robots-Tag: noindex` on the `*.workers.dev` hostname so that previews are not indexed. This uses the documented absolute-URL rule form `https://:version.:subdomain.workers.dev/*`. It was not tested.

### 6. Trailing-slash and canonical policy

Recommendation: **keep trailing slashes** and make everything agree with them.

Evidence on the live site:
- The live sitemap lists all 239 URLs with a trailing slash. Pages are served at the slash URL.
- The slash-less URL answers `301` to the slash URL (for example `/picture/exoplanet` to `/picture/exoplanet/`).
- Only `canonical`, `og:url` and internal links omit the slash, so they point at the URL that redirects.

Decision:
- Astro `trailingSlash: 'always'`, `build.format: 'directory'`, Worker `assets.html_handling: "auto-trailing-slash"` (the default, and the only mode that matches directory output).
- `canonical`, `og:url`, internal links and the sitemap all use the slash form. The parity gate in ADR 0001 compares the slash-form sitemap, which is consistent.
- Do not choose slash-less: it would require `html_handling: "drop-trailing-slash"`, `build.format: 'file'`, and changing both the served URL of every page and the sitemap.

Workers behaviour that differs from Netlify (verified): requests without the slash get **`307`**, not `301`. `/x/index.html` also returns 307 to `/x/`. Neither is configurable via `html_handling`. Mitigation: ensure nothing we emit links to the redirecting form. An optional build step can generate per-page static `301` rules in `_redirects` (up to 2,000 static rules, 239 needed), but redirects run before headers and whether they take precedence over `html_handling` was **not tested**.

### 7. `wrangler.jsonc` the real project needs

```jsonc
{
	"name": "eyesbound",
	"compatibility_date": "2026-10-22",
	"assets": {
		"directory": "./dist",
		"html_handling": "auto-trailing-slash",
		"not_found_handling": "404-page"
	}
}
```

- No `main`, no bindings, no `run_worker_first`: all requests are served as static assets. `_headers` does not apply to responses generated by Worker code, so adding a Worker script later would move headers into code.
- `not_found_handling: "404-page"` is a documented option but was not tested in the spike. Check the 404 response status and the `404.html` page before launch.
- Do not commit this file in the spike. Preview deployments use Version URLs (`wrangler versions upload`; `preview_urls` option). This replaces Pages' per-PR preview and the `_screenshots.yml` Netlify wait. The CI design is out of scope here.

### 8. Free-tier limits (from Cloudflare docs, fetched 2026-10-22)

Sources: Workers [platform limits](https://developers.cloudflare.com/workers/platform/limits/#static-assets), [static assets billing](https://developers.cloudflare.com/workers/static-assets/billing-and-limitations/), [headers](https://developers.cloudflare.com/workers/static-assets/headers/), [redirects](https://developers.cloudflare.com/workers/static-assets/redirects/).

| Item | Workers Free |
|---|---|
| Requests to static assets | free and unlimited |
| Worker script requests | 100,000 per day (only when a script runs, for example with `run_worker_first`; over the limit these get Error 1027 or 429) |
| Static asset files per version | 20,000 |
| Individual file size | 25 MiB |
| `_headers` rules / characters per line | 100 / 2,000 |
| `_redirects` | 2,000 static + 100 dynamic = 2,100 total; 1,000 characters per rule |
| Storage of assets | no additional cost |

Estimate to check at build time: 239 pages plus Astro's generated image variants (158 pictures, several widths, formats) should stay far below 20,000 files, but the file count must be asserted in CI. Git-connected builds ("Workers Builds") and their limits were not researched.

## Behaviour observed (Workers static assets vs Netlify and the agent notes)

- `_headers` works as documented on assets-only Workers. Same file format as Pages.
- Rules accumulate. Duplicate CSP produced two separate `content-security-policy` header lines, not a comma join. Use `! Header` to detach.
- `/picture/:uid/` placeholders match single path segments only, and `/picture/*` includes the listing page.
- Redirects to add or drop the trailing slash are `307`.
- Cloudflare may add default headers at any time; the response also carries `report-to` and `nel` headers.
- The CLI delegates `pages project create` and `pages deploy` to the Workers path (see Context).

## Consequences

**Positive**
- `unsafe-eval` is limited to two route patterns. `unsafe-inline` for scripts disappears everywhere. Strict CSP on all other pages, with the header (not meta), so `frame-ancestors` works.
- `csp-utils.js` is reduced to a hash substitution for at most a few inline scripts, or removed entirely.
- Static-asset requests are free, with no per-request limit, on the free plan.

**Negative / risks**
- The map CSP could not be validated at render time because of the referrer-restricted key. Permissive entries (`'unsafe-eval'`, `blob:` in `script-src`, extra Google hosts) are kept on documentation alone.
- 307 instead of 301 for trailing-slash redirects, and no control over it.
- Overlapping `_headers` rules are easy to get wrong (silent double CSP). A CI test must fetch the built routes through the Worker (or `wrangler dev`) and assert exactly one CSP header per route.
- `/sw.js` kill-switch is required to avoid stale Gatsby caches for returning visitors.

## Follow-up (not done in this spike)

1. Re-run variants a and c (with and without `'unsafe-eval'`) with a key that allows the test origin. Add `https://eyesbound-csp-spike.eyesbound.workers.dev/*` to the key's allowed referrers temporarily, or use a separate test key. Then drop `'unsafe-eval'`, `blob:` and extra hosts if there are no violations. Run the policy as `Content-Security-Policy-Report-Only` first, in line with the CSP rollout rule.
2. Test `_redirects` 301 rules against `html_handling`, `not_found_handling: "404-page"`, and the `X-Robots-Tag` rule.
3. Cutover, DNS, HSTS preload and CSP enforcement need explicit human confirmation.
